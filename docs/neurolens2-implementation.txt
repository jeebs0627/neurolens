IN MIND 2.0 — 구현·검증 인수 문서
작성: 2026-10-22 / 엔진 nl2-2.0.0 / 데이터 계약 nl2-packet-1

1. 제공하는 실행 결과

별도 페이지 /neurolens2.html과 전용 neurolens2/ 모듈을 구현했다.
운영 in_mind 페이지, condition 모듈, NLAuth 클라이언트, 운영 결과 테이블에 연결하지 않는다.
운영 메뉴에서 2.0으로 연결하는 링크도 추가하지 않았다. 2.0은 별도 관리자 연구 페이지로 배포한다.

실행 기능:
• 첫 검사 180초, 일일 60초·90초, 주간 180초의 고정 시간 예산.
• 실제 웹캠 → 독립 Web Worker의 MediaPipe 얼굴/홍채 추적 → 수치 관측.
• 세 교정점과 두 독립 검증점. 지점별 최소 관측 수와 동등 가중치 적용.
• 큰 좌우 관심영역의 공간 가중치, 머리 자세·깜박임·해상도에 따른 보류.
• 중앙 주시 단계에서 지속 편향을 확인하고 이후 시선 근거를 보류.
• 위협·슬픔·긍정 자극의 체류 비율, 정서 자극에서의 시선 전환 시간.
• 시선과 구별된 수동 전환 반응, 잠정 보상 선택, 적응 난이도의 계산 부하.
• 이마·양 볼의 POS/CHROM 후보 비교, 영역 중복 제거, 비중첩 시간 창.
• 배경 밝기 혼입·관측 단절·ROI 불일치 시 심박 후보 보류.
• 부하 상승량이 후보 오차보다 충분히 클 때만 잠정 회복률 산출.
• 관리자·참여 코드별 전용 IndexedDB 기록, JSON 내보내기·재분석.
• 같은 조건의 이전 날짜만 사용하는 초기/이동 개인 기준선.
• 실제·합성·가져온 기록의 분리, 근거 원천과 후보 채택 이력 표시.
• 기준 신호와 비교할 수 있는 오프라인 벤치마크 도구.

2. 지금 실행하는 방법

프로젝트 폴더의 PowerShell에서:
  powershell -ExecutionPolicy Bypass -File .\start-neurolens2.ps1

기본 포트는 8872이며 이미 사용 중이면 빈 포트를 선택한다.
Windows에서도 소켓 독점 바인딩을 사용해 여러 실행기의 티켓이 뒤섞이지 않게 한다.
실행기는 127.0.0.1에만 바인딩한다. 외부 네트워크 접속은 받지 않는다.
Windows 사용자에게 10분 유효·1회 사용 입장 주소를 발급하고 브라우저를 연다.
입장 시 주소의 티켓을 제거하고 HttpOnly·SameSite=Strict 쿠키로 8시간 로컬 세션을 유지한다.
로그아웃 후에는 실행기를 다시 실행해 새 입장 주소를 받는다.
실행 상태 파일과 비밀 입장 주소는 %LOCALAPPDATA%\NeuroLens2에만 기록한다.
서버 종료: 실행기에 표시된 PID에 대해 Stop-Process -Id <PID>.

권장 첫 확인:
① 합성 신호로 엔진 확인 → 실제 사람의 결과와 구분되는지 확인.
② 결과 JSON 내보내기 → 가져오기 → 같은 근거와 결과가 재현되는지 확인.
③ 연구 참여 코드 설정 → 첫 측정 180초 → 카메라 사용 → 화면 안내에 따라 수행.
④ 카메라를 쓸 수 없으면 명시적으로 행동 과제 모드를 선택.
⑤ 동일 참여 코드·장치·화면 크기·프로토콜·형식으로 여러 날짜 반복.

카메라 모델 준비와 이미지 준비는 측정 시작 전에 끝낸다.
준비 시간, 검사 시간, 전체 경과 시간은 구분하여 기록한다.
탭 가림, 다른 창 이동, 화면 크기 변경, 카메라 종료, 긴 프레임 지연은 중단 사유가 된다.
부족한 신호를 얻기 위해 검사 시간을 자동 연장하지 않는다.

3. 배포 환경의 관리자 접근

Vercel에서 /api/neurolens2 Python 함수가 세션을 검증한다.
서버 환경변수 NEUROLENS2_ADMIN_IDS에 허용할 Supabase Auth 사용자 UUID를 쉼표로 등록해야 한다.
예: NEUROLENS2_ADMIN_IDS=<관리자 Auth UUID>,<두 번째 관리자 Auth UUID>
2026-10-22: 기존 관리자 계정의 Auth UUID를 Vercel Production과 Preview 허용 목록에 설정했다.
원격 접속 주소: https://www.neurolens.me/neurolens2.html
이 주소는 배포 완료 후 기존 뉴로렌즈 관리자 이메일과 비밀번호로 입장한다.
로컬 일회용 주소는 원격 서버에서 사용할 수 없다. 비밀번호는 발급하거나 변경하지 않았다.

인증 단계:
① 실제 /auth/v1/user 요청으로 토큰의 사용자 확인.
② 서버 허용 목록에 포함되는지 확인.
③ 사용자 JWT로 기존 public.is_admin() RPC가 정확히 true인지 확인.
④ 통과한 경우만 연구 앱을 부트스트랩하고 주기적으로 권한 재검증.

기존 profiles_update_own 정책만으로는 role 필드 변경 제한을 확인할 수 없으므로,
기존 프로필의 admin 문자열만 믿지 않고 별도 서버 허용 목록을 필수로 두었다.
허용 목록 미설정, 인증 네트워크 장애, 일반 계정, 잘못된 RPC 응답은 모두 접근 보류다.
서버에는 결과 저장 기능과 임의 RPC 프록시가 없다. service role 키를 사용하지 않는다.
운영 인증 스토리지 대신 neurolens2-auth-v1이라는 별도 sessionStorage를 사용한다.
로그아웃은 2.0의 로컬 토큰과 로컬 미리보기 쿠키만 정리한다.

HTML 로그인 셸과 JavaScript는 정적 자산이다. 이 구조는 소스코드 비공개 저장소가 아니다.
서버 권한 검증은 정상 앱 진입 경계이며, 운영 데이터에 접근할 수 있는 권한은 앱에 제공하지 않는다.
연구 소스 자체의 비공개 배포가 필요하면 별도 비공개 미리보기 배포의 접근 보호가 추가되어야 한다.

4. 시간표와 과제

first180: 교정18 → 기준12 → 정서주의36 → 전환24 → 보상18 → 부하전20 → 부하20 → 회복28 → 마무리4.
daily60: 교정10 → 기준12 → 선택과제24 → 회복10 → 마무리4.
daily90: 교정12 → 기준20 → 선택과제30 → 회복24 → 마무리4.
weekly180: 교정18 → 기준22 → 선택과제48 → 부하전20 → 부하24 → 회복44 → 마무리4.
단위는 초다. 모든 시간표는 순수 엔진의 schedule()로 고정하며 테스트로 총 시간을 확인한다.

정서 주의 시행은 2.5초, 전환·보상·계산 시행은 3초다.
정서 범주 순서를 시드에 따라 섞고 범주별 좌우 배치를 균형화한다.
A/B 각각 위협·슬픔·긍정 4쌍, 총 24쌍(48장)을 별도 복사해 해시를 고정했다.
자극은 기존 프로젝트의 잠정 자극이다. 인간의 정서가·각성도 평정은 완료되지 않았다.
자극 생성 모델이나 정서 평정의 신규 검증을 했다고 주장하지 않는다.

일일 자동 과제는 최근 실제 관측에서 유효 시행이 적은 축을 선택한다.
행동 모드에서 시선 주의가 추천되면 버튼 전환 과제로 변경한다.
첫 측정은 주의·전환·보상·부하·회복 모두를 수행한다.
일일 모드에는 부하 단계가 없으므로 부하 후 회복률을 억지로 산출하지 않는다.
보상 결과는 짧은 선택 과제의 기술 통계이며 무쾌감 또는 강화학습률로 해석하지 않는다.
계산 난이도는 반응에 따라 바뀐다. 계산 반응 시간은 난이도 구성과 함께 검토해야 한다.
개인 비교에서도 계산 난이도 구성과 심박의 채택 단계·시간 창이 같을 때만 기준선을 만든다.

5. 독자 구현과 출원 아이디어의 연결

출원1 관련 구현:
• 시선과 RGB 맥파의 같은 카메라 의존성을 원천 그룹으로 명시한다.
• 서로 다른 지표 수를 독립 모달리티 수로 과대 계산하지 않는다.
• 관측 부족, 교정 실패, 품질 불일치에서 결과를 보류한다.
• 개인·장치·과제·형식·버전·교정 등급의 비교 조건을 분리한다.
현재 미구현: 학습된 공분산 상태모델, 시간척도가 정합된 주관-객관 불일치 모델.

출원2 관련 구현:
• ROI·방법·시간 창·부모 원천을 가진 후보 장부를 저장한다.
• 같은 픽셀의 POS와 CHROM은 독립 지지로 중복 합산하지 않는다.
• 공간 영역 중첩과 프레임 시간 중복을 제거한다.
• 보간점은 주파수 계산에만 쓰며 실제 관측 수를 늘리지 않는다.
• 단계 경계를 넘거나 서로 겹치는 창을 회복의 독립 근거로 쓰지 않는다.
• 회복 분모가 후보 불확실성보다 작으면 회복률을 만들지 않는다.
현재 미구현: 딥러닝 후보 결합, calibrated covariance/uncertainty, 특허 전체 청구항의 법률적 실시 검토.

이 조합의 코드와 연구 흐름이 독자 개발 영역이다.
MediaPipe, POS, CHROM은 공개 선행 기술이며 자체 발명으로 표시하지 않는다.
특허 등록·청구항 충족·법률상 신규성 또는 경쟁사 대비 우월성을 확정한 문서는 아니다.

6. 데이터 계약과 재현

세션에는 engine, schema, id, participant(해시), protocol, focus, form, seed,
deviceKey(해시), 장치 해상도/FPS, 단계 시간표, 시행, 수치 프레임, 교정점,
사건 로그, 준비/총 시간, 중단 사유, 계산된 결과를 기록한다.
수치 프레임: 상대 시간·영상 시각, 얼굴 품질, 홍채 상대 위치, 머리 자세,
ROI별 평균 RGB·포함 비율·영역 사각형, 배경 밝기 등.
원본 영상·음성·얼굴 랜드마크 배열·이미지·인증 토큰은 결과에 넣지 않는다.
참여 코드 원문은 검사 설정에만 두고 결과에는 관리자 범위와 결합한 해시를 사용한다.

재생 입력은 최대 8MB, 12,000 프레임, 100 시행, 3,000 교정 관측이다.
계약 버전, 시간표, 수치, 중첩, 토큰 필드, prototype 오염 필드를 검사한다.
저장된 calibration과 result를 그대로 믿지 않고 교정부터 다시 계산한다.
가져온 JSON은 수정 가능하므로 진본 인증을 주장하지 않고 imported로 분리한다.
브라우저에 저장된 실제 기록만 개인 기준선 후보가 되며 합성·가져온 기록은 제외한다.
현재 스키마에 맞지 않는 미래/과거 엔진은 자동 점수 변환 없이 거부한다.
장기적인 과거 엔진 재생을 위해 후속 릴리스마다 엔진 번들을 보존해야 한다.

7. 검증 실행

  python -X utf8 tools/neurolens2_verify.py --browser

Node.js와 Python이 필요하다. 기본 검증은 저장소의 독립 Node 테스트와 Python unittest다.
브라우저 검증에는 Playwright와 로컬 Edge가 필요하다.
현재 환경에서는 Codex에 번들된 Node/Python/Playwright를 사용했다.

검증 항목:
• 엔진/벤치마크 23건: 시간 예산, 시드 재현, 범주별 좌우 균형,
  독립 검증점, 부족한 검증점 거부, 시선 제외 조건, 관측 주기,
  수동/시선 분리, 72bpm 합성 신호, 평탄·누락·조명·ROI 중복,
  프레임 복제, 중앙 주시 편향, 비중첩 창, 회복 분모, 개인 날짜 분리,
  계약 검증, 합성 제외, 피험자 누수, 피험자 평균 오차, 부트스트랩 등.
• 인증/로컬 서버 12건: 실제 사용자 검증 호출, 허용 목록, admin RPC,
  위조 메타데이터, 장애 차단, 경로 제한, DNS rebinding 방어,
  교차 출처 차단, 일회용 티켓, 쿠키/로그아웃, 실행기 중복 실행 시 포트 독점.
• 브라우저 12개 흐름: 로그인, 합성 분석, JSON 왕복 재현, 모바일,
  60초 응답, 180초 전 단계, 포커스 이탈, 로그아웃,
  실제 MediaPipe WASM/모델 로딩, 빈 영상 보류/스트림 해제,
  카메라 거부 복구, 비인증 차단, 운영 모듈 미요청.

검사 시간 제어는 브라우저 테스트에서 테스트 영역의 가상 애니메이션 시계로 가속했다.
프로덕션 코드에는 테스트 인증 우회나 가짜 카메라 쿼리 파라미터를 넣지 않았다.
실제 모델 로딩 검사는 실제 Web Worker와 WASM을 실행하고 테스트용 빈 영상만 입력했다.
따라서 얼굴 추적 정확도, 인간 심박 오차 또는 정서 타당도를 검증한 결과는 아니다.

자동 생성 근거: output/neurolens2/verification.json, browser-test-results.json,
데스크톱/모바일 스크린샷, synthetic-session.json, replayed-session.json, behavior-session.json.

t는 세션 시작과 정렬된 밀리초다. 창당 6개 이상, 9초 이상의 기준값 범위를 요구한다.
단위 변환과 카메라/기준 신호의 시각 정렬은 원자료 어댑터에서 먼저 수행해야 한다.
기준 신호를 보고 가장 유리한 시간 오프셋을 고르는 절차는 허용하지 않는 연구 설계가 필요하다.
허용된 데이터셋의 영상을 수치 패킷으로 변환하는 데이터셋별 어댑터는 별도 작업이다.

도구는 동일 피험자의 train/dev/test 중복을 거부한다.
POS(이마), CHROM(이마), 다중 ROI 채택 결과를 같은 기준 창에서 비교한다.
유효 비율, MAE/RMSE/편향, 피험자별 MAE와 동등 가중 평균을 함께 보고한다.
5명 이상일 때만 피험자 단위 재표집으로 MAE 구간을 계산한다.
합성 기준과 실제 장비 기준은 같은 보고서에 혼합하지 않는다.
공개 데이터셋 다운로드·사용권 확보·실제 데이터 평가를 수행한 상태는 아니다.

9. 로드맵 추적 — 완료의 의미를 구분

T01 기준/출원 대응: 코드 경계·보존 해시·이 문서 구현.
T02 데이터 계약: 수치 패킷, 시각, 원천, 교정, 시행, 품질, 버전 구현.
T03 재생/실패 주입: 결정적 재계산과 합성/누락/중복/조명 테스트 구현.
T04 카메라 품질: 장치 설정, ROI 포함 비율, 얼굴/자세/해상도/연속성 구현. 실기기 분포 검증 남음.
T05 AOI/짧은 교정: 수평 교정·독립 검증·가중 AOI·편향 감지 구현. 확률 교정은 미완료.
T06 정서 항목 은행: A/B 잠정 24쌍 고정. 인간 평정과 문화권 타당도 남음.
T07 자유 보기: 구현. 과제 신뢰도는 미검증.
T08 정서 이탈: 시작 주시 확인·지속 전환·수동 반응 분리 구현. 정밀 장비 대비 지연 검증 남음.
T09 대비 통계: 시행 통계·변동 구간 구현. 혼합효과·잠재 정서 추정 모델은 미구현.
T10 공개 맥파 비교: 기준 비교 도구 구현. 데이터셋 어댑터/실제 벤치마크 남음.
T11 혼합 맥파/계보: 공개 POS/CHROM과 영역·시간·방법 계보 구현. 신경망 후보/오차 교정 남음.
T12 회복 모델: 비중첩 창·분모 게이트·잠정 회복률 구현. 생리 타당도/느린 회복 모델 남음.
T13 시간 예산: 60/90/180초 고정 실행·중단·준비 분리 구현.
T14 개인 기록: 관리자/참여자별 전용 로컬 저장·내보내기·가져오기 구현.
T15 개인 기준선: 이전 독립 날짜·고정/이동 기준·조건 분리 구현. 개인 상태 학습은 미구현.
T16 정서 리포트: 실제 반응·표본 수·불확실성 종류·채택 이유·보류 설명 구현.
T17 반복 파일럿: 수집·수출 가능한 실행기 마련. 사람 대상 반복 수집은 수행 전.
T18 파일럿 분석: 실데이터 부재. 정서 ICC/SEM/일반화 분석은 수행 전.
T19 보상: 짧은 선택·확률 피드백·원자료 구현. 강화학습 모수 추정은 미구현.
T20 개인 상태공간: 미구현. 현재의 강건한 기준선을 학습 모델이라고 부르지 않는다.
T21 정보량 적응: 관측 수 기반 탐색 규칙만 구현. EIG 학습·동등시간 무작위 비교 남음.
T22 회복 개입: 미구현. 현재는 자연 회복 관측이며 개입 효과를 주장하지 않는다.
T23 글로벌 확장: 반응형 한국어 UI 구현. 실제 기기/피부색/언어권 시험 남음.
T24 승격/회귀: 자동 회귀 검사·기존 파일 보존 검사 구현. 원격 배포·운영 승격은 하지 않음.

10. 다음 개발 순서와 통과 조건

첫째: 실제 관리자 반복 수집으로 카메라 실패 원인을 먼저 파악한다.
같은 장치 3개 날짜의 60/90/180초 기록을 모으고 검출 실패, 눈 해상도,
교정 등급, 심박 후보 창 유효 비율, 시선 유효 시행을 조건별로 집계한다.
정답이 없는 상태에서 보류 기준만 낮춰 성공률을 높이지 않는다.

둘째: 사용권이 확보된 공개 RGB-PPG 영상의 변환 어댑터를 만든다.
원본 시간·ROI·기준 시각을 보존하고 피험자 분리를 고정한다.
POS/CHROM과 새 딥러닝 후보를 동일 데이터·창·기준 신호로 비교한다.
조건별 유효 비율과 오차가 동시에 개선될 때만 새 후보를 기본으로 승격한다.

셋째: 정서 자극 평정과 7~14일 반복 자료로 유효한 축을 선택한다.
시행 수, 동일 자극 반복, A/B 등가성, 시선 실패와 버튼 전환의 차이를 평가한다.
유효한 축만 개인 상태 모델의 관측값으로 사용하며, 불안/우울 관련성을 별도로 검증한다.

넷째: T20 상태모델과 T21 적응 선택을 'shadow'로 구현한다.
초기에는 결과를 바꾸지 않고 제안·불확실성·후속 실제 관측 오차만 기록한다.
고정 과제와 같은 60/90초 예산에서 다음 날짜 예측/반복 안정성이 개선되는지 확인한다.
독립 평가 이전에는 adaptive 추천을 검증된 정밀 측정으로 표시하지 않는다.

다섯째: T22의 개인 회복 개입을 무작위 교차 비교한다.
쉬기/호흡/주의 전환의 실제 관측 반응을 누적한 뒤 개인에게 맞는 선택을 학습한다.
이 단계에서 정서 기능 데이터·상태 추적·개입 반응의 결합이 장기 기술 해자가 된다.

현재 완성한 것은 실제 실행·기록·설명이 가능한 독립 연구 버전이다.
진단 모델, 인간 측정 정확도, 공개 데이터 성능, 세계 최고 성능의 검증까지 완료한 상태는 아니다.
